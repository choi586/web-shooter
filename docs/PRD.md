# WEB SHOOTER 상세 PRD

## 1. 제품 정의

손목의 micro:bit를 착용한 체험자가 손목을 꺾고 팔을 빠르게 뻗으면, 대형 화면의 1인칭 웹슈터에서 거미줄이 발사되어 목표에 자동 명중하는 30~60초 피지컬 인터랙션 콘텐츠다.

핵심 경험은 한 문장으로 고정한다.

> 내가 손을 뻗는다 → 화면에서 동시에 웹이 발사된다.

정확한 조준 게임이나 캐릭터 이동은 넣지 않는다. 동작과 화면 반응 사이의 짧은 지연, 웹의 질감, 명중 피드백에 완성도를 집중한다.

## 2. 성공 기준

- 별도 설명을 듣지 않은 참가자 10명 중 8명 이상이 10초 안에 첫 발사를 성공한다.
- 유효한 `WEB` 신호는 정확히 한 번 명중하며 650ms 안의 중복 신호는 추가 득점되지 않는다.
- 신호 수신부터 첫 화면·음향 반응까지 p95 150ms 이하, 착탄까지 600ms 이하를 목표로 한다.
- 정상 발사는 모두 명중한다. 실패, 감점, 빗나감 화면은 없다.
- 첫 발사부터 결과 화면 종료까지 기본 설정에서 약 40~55초다.
- USB 분리, 새로고침, 장치 선택 취소, 장시간 무입력 후에도 화면이 고착되지 않는다.

## 3. 대상과 운영 환경

- 행사, 전시, 오픈캠퍼스, 메이커 체험 부스
- 참가자 1명씩 약 45~50초 회전
- 16:9 대형 모니터 또는 프로젝터
- 최신 데스크톱 Chrome과 HTTPS 주소
- micro:bit v2 2개, 손목밴드, A용 배터리 팩, B용 데이터 USB 케이블

## 4. 시스템 구성

```text
손목 micro:bit A
  └─ 손목 각도 + 순간 가속 판정
       └─ micro:bit Radio: W|boot|sequence|time
            └─ USB 수신기 micro:bit B
                 └─ 115200 USB Serial: WS1|WEB|...
                      └─ Web Serial API
                           └─ shootWeb()
```

A는 발사 자세를 100ms 유지한 다음 1.2초 안에 별도의 순간 가속이 들어올 때만 발사한다. 한 번 발사하면 650ms 잠기고 손목이 발사 자세를 벗어나야 다시 준비된다.

B는 A의 패킷을 확인해 ACK를 되돌려주고, 재전송된 중복 패킷은 제거한 뒤 웹앱에 한 줄만 전달한다. 1초마다 상태 신호를 보내 연결 이상을 감지한다.

## 5. 체험 상태

| 상태 | 동작 |
|---|---|
| ATTRACT | `손목을 꺾고 → 앞으로 촥!` 안내를 반복한다. 첫 실제 발사는 세션 시작과 동시에 1 HIT로 반영한다. |
| PLAY | 기본 35초. 목표 1개만 활성화하며 모든 정상 발사는 자동 명중한다. 남은 시간은 마지막 5초에 숫자로 강조한다. |
| SHOT | 0~100ms 반동·발사음, 100~450ms 웹 비행, 약 285ms 명중, 560ms 다음 목표 이동, 650ms 입력 잠금 해제. |
| RESULT | 5초간 `N HIT — 멋진 발사!`와 총점을 보여준다. 순위와 실패 문구는 없다. |
| PAUSE | Serial로 시작한 체험에서 수신기 응답이 끊기면 시간이 멈춘다. 10초 안에 복구하면 이어서 진행하고, 아니면 ATTRACT로 복귀한다. |

PLAY 중 8초 동안 발사가 없으면 동작 안내를 강조한다. 20초 무입력이면 결과를 기록하지 않고 ATTRACT로 돌아간다.

## 6. 화면과 자동 조준 연출

- 16:9 야간 도시, 굵은 잉크 외곽선, 하프톤 질감
- 색상: 네이비 `#081527`, 레드 `#ff3d4a`, 시안 `#51efff`, 옐로 `#ffd83d`, 크림 `#f7efda`
- 화면 아래에는 독자적인 1인칭 팔과 웹슈터 장치만 보인다.
- 목표는 중앙 안전 구역의 7개 위치 중 하나에 나타나며 같은 위치를 연속 사용하지 않는다.
- 발사 순간 3가닥의 웹, 80~120ms 반동, 짧은 스피드라인으로 자동 조준 보정을 숨긴다.
- 착탄 시 목표 확대·수축, 웹 스플랫, `HIT! +100`, 화면과 독립적인 음향을 함께 사용한다.
- 참가자에게 조준선이나 센서 수치를 보여주지 않는다.

## 7. 효과음

외부 음원 없이 Web Audio로 현장에서 합성한다.

- 발사: 짧은 톤 하강 + 밴드패스 노이즈
- 착탄: 저음과 중음의 짧은 상승 코드
- 결과: 4음 성공 스팅어

브라우저 정책상 운영자가 처음 `운영 시작` 또는 연결 버튼을 눌렀을 때 사운드를 활성화한다. 음소거 상태에서도 텍스트, 목표 반응, 웹 스플랫으로 성공 여부를 알 수 있어야 한다.

## 8. 입력과 통신

- 공식 입력: micro:bit B의 Web Serial
- 비상 대체 입력: `Space`
- 수신기 단독 시험: B의 A 버튼
- 운영자 시험: 패널의 `시험 발사`
- 자동 데모: 3~5초의 불규칙한 간격, 실제 통계에 포함하지 않음

브라우저 파서는 줄이 여러 USB 청크로 나뉘거나 여러 줄이 한 청크에 들어오는 경우를 모두 처리한다. 최대 줄 길이, 필드 형식, 숫자 범위를 검증하고 알 수 없는 문자열은 무시한다. 동일한 `boot_id + sequence`는 한 번만 처리한다.

## 9. 운영자 패널

- 장치 연결·해제, 최근 신호, RSSI, 수신·중복 제거 수치
- 시험 발사, 강제 초기화, 자동 데모
- 30/35/45초 세션 길이
- 왼손/오른손 화면
- 음소거, 볼륨, 움직임 줄이기
- 전체화면
- 당일 완료 세션과 실제 발사 수

단축키는 `Space` 발사, `R` 초기화, `D` 데모, `M` 음소거, `F` 전체화면, `O` 운영 설정이다.

## 10. 접근성·안전

- 안내 글자는 1080p에서 큰 거리에서도 읽을 수 있는 크기와 4.5:1 이상의 대비를 목표로 한다.
- 성공 여부를 색상이나 소리 하나에만 의존하지 않는다.
- 움직임 줄이기에서는 화면 흔들림, 강한 스피드라인, 과도한 반동을 제거한다.
- 초당 3회가 넘는 점멸과 전체 화면 흰색 플래시는 사용하지 않는다.
- 왼손·오른손을 선택할 수 있고 목표를 화면 가장자리에 배치하지 않는다.
- 참가자가 서로 부딪히지 않도록 팔을 뻗는 체험선과 대기선을 바닥에 분리 표시한다.

## 11. 현장 수용 시험

1. 장치 선택 취소 후 다시 연결
2. USB 분리 후 10초 안에 재연결
3. USB는 유지한 채 B 리셋
4. 전원 전용 케이블과 데이터 케이블 구분
5. MakeCode 콘솔이 포트를 점유한 상태의 안내 확인
6. A+B 시험 발사와 B의 A 버튼 시험
7. 동일 패킷 3회 수신 시 화면 1회 반응
8. 줄이 임의 위치에서 분할된 Serial 데이터 파싱
9. 500회 연속 발사 중 상태 고착과 메모리 증가 확인
10. 음소거, 움직임 줄이기, 왼손 모드 확인

## 12. 제외 범위

- 손가락 모양 자체를 카메라나 flex 센서로 판정
- micro:bit 가속도만으로 정밀 조준
- 캐릭터 전신 이동, 웹스윙, 랭킹, 실패 판정
- Safari, iOS, Android를 공식 행사 브라우저로 지원
